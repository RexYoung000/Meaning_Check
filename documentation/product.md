# 产品规则

## 目的与成功条件

Rex 在 Dia 阅读公开英文 X 回复时，能更快读懂语气和可能含义。成功不是给出任何解释，而是相较字面翻译增加可检查的理解，并有明确主方向。实际价值由真实日常案例验收。

## 已确认

- 首版支持公开英文 X 回复，整条回复点击分析；hover / focus 显示「帮我确认意思」。
- 浮层旁显，不改写原文；一句中文主解读先行，语气、表达功能和 1–2 条依据随后。
- 输入为当前回复、直接父帖、原帖，父帖等于原帖时去重。引用帖不是父帖。
- 缺失上下文先自动补齐。失败须提示缺失项，由用户选择部分分析、重试或手动补充。部分分析仍标明缺失，不能假装完整。
- 纯文本、俚语、缩写、emoji。媒体内容未解析，遇到图片 / GIF 明示覆盖限制。
- 语气与表达功能独立；反驳不等于恶意。不凭个人资料、国籍推断意图，不保证他人内心动机。
- 主方向可判断时先给结论，次要歧义随后；主方向无法判断时说明需要何种上下文。不使用虚构准确率或置信百分比。
- DeepSeek V4.1 Flash，自带本地密钥，不保存分析历史。
- 首版不含私信、Reddit、澄清问题生成、回复写作、自动发送、账号、订阅或商业服务。

## 工程默认

工程名 Meaning_Check。上下文最多追溯 10 层、30 秒；一次模型输入不超过 12,000 字符，输出上限 4,096 token，总超时 60 秒，不自动重发。补齐仅关闭插件自建临时页，不影响用户页面。

## 当前实现与对齐复核

阶段：建档完成、业务功能尚未实现。以上条目均来自已确认的讨论；纯文本范围和补齐失败的用户选择已对齐。没有需要扩大范围才能开发的未决问题。

待实测而非待选择：X 页面祖先关联能否可靠识别，Dia MV3 运行行为，真实模型输出质量、延迟和用量。无法可靠确定的父帖 / 根帖必须显示缺失，不能用相邻帖子猜测。
